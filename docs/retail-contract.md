# Retail API contract
All routes use existing session + CSRF and tenant RLS. Writers: tenant_admin/operator (campaign review tenant_admin only). Viewer/store_operator reads are restricted to authorized stores; no campaign writes. No provider/external calls. Dates YYYY-MM-DD; weekdays ISO 1=Monday..7=Sunday; HH:mm; start>end crosses midnight, start=end=00:00 explicitly means 24 hours (other equal times rejected); max campaign range 366 days.

- GET /api/retail/stores -> [{...store,profile:{region:'',tags:[],openingHours:[{weekdays:[1,2,3,4,5,6,7],start:'09:00',end:'22:00'}],closedDates:[],context:null|{observedAt:ISO,weather:'sunny',temperatureC:25}}}]. Unconfigured profile uses 09:00–22:00 daily, explicitly returned.
- PUT /api/retail/stores/:id -> same item; body is profile above. Opening intervals cannot overlap, including previous-day spillover. Campaign dates/weekdays belong to the campaign window start day; store hours belong to their opening day. Closed dates block the entire local calendar day, including spillover from the previous night. A full day is split at local noon without losing midnight minutes. Region/tags arbitrary bounded operator labels.
- GET /api/retail/campaigns -> campaign array; POST /api/retail/campaigns; PUT /api/retail/campaigns/:id. Save body `{name,advertiser,product,mediaId,fillerMediaId,startDate,endDate,weekdays,startTime,endTime,spotSeconds:15|30,cycleSeconds:300|600,storeIds:[],region:'',tags:[],budget:null|number,controlStoreIds:[],weather:[],minTemperatureC:null|number,maxTemperatureC:null|number,audioMode:'muted'|'video',volume:0..1}`. Empty storeIds means all permitted stores filtered by region and tags (all requested tags). Empty region/tags/weather means no corresponding filter. At least one target required at publish. Image creative uses spot duration; video duration must be within 0.5s and actual duration is used. Filler must be image. Campaign ad audioMode defaults muted; optional video plays the creative audio only on the assigned audio screen, with volume default1. Filler is always muted. Weather/temperature use only supplied context no more than 6h old at publish; absent/stale context excludes store. Opening hours and closures are snapshotted at publish.
- Campaign returned `{id,tenantId,name,revision,state:'draft'|'submitted'|'approved'|'rejected'|'published',config:<body>,reviewReason,approvedRevision,createdAt,updatedAt}`. Editing resets state to draft and invalidates approval; published history retained. After first publication, startDate/endDate and controlStoreIds are fixed for historical analytics (create a new campaign to change these). Creative changes remain attributed through each immutable publication/version. List/detail config storeIds and controlStoreIds are restricted for store-scoped readers; campaign visible only if at least one current or published target store is authorized.
- GET /api/retail/campaigns/:id -> campaign.
- POST /api/retail/campaigns/:id/submit `{}` -> campaign.
- POST /api/retail/campaigns/:id/review `{decision:'approved'|'rejected',reason:'...'}` -> campaign; nonempty reason required.
- POST /api/retail/campaigns/:id/publish `{retryFailed?:boolean}` -> report. Only matching approved revision (or published revision) allowed. Repeated publish returns same publication; explicit retryFailed retries failed/cancelled attempts only. No pending deployment replacement. Templates/versions immutable per publication/store; records keep deployment IDs and targeting snapshots. At most 100 targeted groups per publication.
- GET /api/retail/campaigns/:id/report -> `{campaign,publications:[{id,revision,createdAt,config,storeSnapshots}],deployments:[{id,publicationId,storeId,groupId,deploymentId,attempt,status,errors}],delivery:{deviceReportedCompletions,reportedDeviceCount,reportedGroupCount,plannedGroupSpots,estimateLabel},perStore:[{storeId,name,deviceReportedCompletions,reportedDeviceCount,reportedGroupCount,plannedGroupSpots}],pos:{rows:[{storeId,date,sku,units,revenue}],comparison:{beforeStart,beforeEnd,campaignStart,campaignEnd,exposed:{before:{units,revenue},during:{units,revenue}},control:{before:{units,revenue},during:{units,revenue}},note}},survey:null|{responses,aware,intendAware,awareBase,intendUnaware,unawareBase},disclaimer}`. PlannedGroupSpots is schedule opportunity per display group, not impressions/people or proven plays; actual is deduplicated device claims (multi-screen devices counted separately). POS before period equals campaign date span immediately preceding start. Explicit controlStoreIds only; no causal lift assertion. comparison.exposed/control.before/during include coverage {observedStoreDays,expectedStoreDays,observedStoreDaySkus,expectedStoreDaySkus,complete}. comparison.skus lists selected imported SKU set. comparison.metrics.units/revenue provide {exposedGrowthPct,controlGrowthPct,differencePercentagePoints}; missing/incomplete coverage or zero baseline yields null (never fabricated zero control growth). Survey is aggregate operator supplied; unavailable for store-scoped readers because it cannot be safely split by store.
- POST /api/retail/campaigns/:id/pos `{rows:[{storeId,date,sku,units,revenue}]}` -> `{imported:n}` (upsert campaign/store/date/sku; 1..1000 rows; only targeted or explicit control stores, dates in campaign or equal prior period).
- POST /api/retail/campaigns/:id/survey `{responses,aware,intendAware,awareBase,intendUnaware,unawareBase}` -> same object. Counts integers >=0; aware<=responses, awareBase<=aware, unawareBase<=responses-aware; intention counts <= corresponding bases.

Campaign publish explicitly replaces the selected groups' current assignment after normal preparation; outside campaign windows the supplied filler image plays. No automatic publish, POS fetch, or weather fetch. API JSON report is canonical export; console can derive CSV.
